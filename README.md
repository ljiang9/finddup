# finddup

按内容哈希（SHA-256）找出重复文件的小工具。纯标准库、纯本地、**只读**。

## 快速开始

```bash
cd ~/workspace/ai-forks/finddup
python3 -m finddup ~/photos
python3 -m finddup ~/downloads --min-size 1M
python3 -m finddup . --exclude "*.tmp" --exclude "__pycache__"
```

## 参数

| 参数 | 说明 |
|---|---|
| `directory` | 要扫描的目录 |
| `--min-size SIZE` | 只考虑不小于该大小的文件，如 `1M`、`500K`（默认 1 字节） |
| `--exclude PATTERN` | 排除模式（fnmatch），可重复 |
| `--json` | 输出 JSON（含扫描数、分组、可回收字节数） |
| `--script` | 输出 `rm` 命令（每组保留第一个），供审查后执行 |
| `--version` | 版本号 |

## 为什么没有 `--delete`？

删除文件不可逆。重复文件里哪个该留、哪个该删是人的判断（比如两份
"相同" 的合同扫描件，一份在归档目录、一份在工作目录，删错会出事）。
所以本工具只做"找"，删除用 `--script` 生成命令、你审查后再执行。

## 两阶段算法

1. 先按**文件大小**分组——大小唯一的直接排除，不读内容；
2. 只对"同大小 ≥ 2 个文件"的组做 SHA-256，再按哈希分组。

大多数文件在第一步就被排除，磁盘读取量远小于全量哈希。

## 链接处理

- **符号链接**：跳过不跟随（避免循环、避免把链接目标算两遍）。
- **硬链接**：同一 inode 只计一次——同一个文件有多个名字，它不是重复。

## 已知局限

- 只读：本工具永远不删除文件（设计如此）。
- 大文件首次扫描需要读完全部字节；同一目录反复扫没有缓存。
- 文件名含换行符等极端情况时，`--script` 输出仍是 shell 安全的（已做引用）。
- 比较的是**内容字节**，元数据（修改时间、权限）不同不算差异。
